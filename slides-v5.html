03 / the operating model
Agentic product development
The builder orchestrates.
The agent executes.
The CTO calls this “Service as Software” — not better tools with AI features, but automated delivery of outcomes. This kit applies that thesis reflexively: the builder writes a PRD. The agent delivers a working prototype. IDS-compliant, accessible, Figma-synced.

Four steps. Two are the builder's: define the problem, judge the solution.
agentic workflow — service as software
STEP 1 ─── scaffold (automated)
$ ./scaffold.sh ✓
 
STEP 2 ─── write PRD ★ (builder)
$ vim docs/PRD.md
"I am a PM trying to validate..."
 
STEP 3 ─── agent builds (automated)
$ claude "Read the PRD and build it"
→ generating design.md...
→ selecting IDS components...
→ building accessible UI...
→ syncing to Figma...
 
STEP 4 ─── review ★ (builder)
"Make the nav sticky and add empty state"
