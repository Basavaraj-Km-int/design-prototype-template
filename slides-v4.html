02 / The problem
The friction tax
Builders want to prototype.
The toolchain blocks them.
Setup takes days, not minutes
Node versions, IDS peer deps, PostCSS, Vite — walls of errors before a single component renders.
IDS breaks in modern tooling
Table, Dropdown, TextField have CSS Module hash conflicts. Workarounds aren't documented.
Figma and code drift apart
No feedback loop. Code goes stale, designs go stale, prototypes lose credibility.
AI agents don't speak Intuit
Claude, Cursor, Copilot guess at IDS props, ignore brand tokens, skip D4D methodology.

04 / How it works
Agentic product development
Four steps.
Two are yours.
You define the problem and judge the output. The AI agent handles everything else — design artifacts, component selection, code, and iteration. This is agentic product development.
1
Scaffold
One command installs React, IDS components, brand tokens, Storybook, MSW mocks, and MCP proxy. ~2 minutes.
2
Write your PRD
Fill in docs/PRD.md — the problem statement. This is the only file you write. PMs, designers, anyone.
3
Agent builds
Claude Code reads your PRD, generates design artifacts, and builds the prototype screen by screen with real IDS components. You don't write code.
4
Review and iterate
See it in your browser, give feedback in plain language, capture to Figma. The builder judges; the agent executes.

10 / Accessibility
Built in, not bolted on
WCAG 2.1 AA is
automatic.
Every IDS component is accessible by default. The agent harness enforces accessibility patterns in generated code. Builders don't think about compliance — they get it.
Semantic HTML
button for actions, a for navigation, landmarks. Never div onClick.
Keyboard navigation
Logical tab order, focus traps in modals, skip-to-content links.
Contrast and visibility
4.5:1 text contrast. 3:1 focus indicators. 44x44px touch targets.
Motion and preferences
prefers-reduced-motion respected. aria-live for updates. Every input labeled.
